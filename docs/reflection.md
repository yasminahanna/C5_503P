# Reflection

**Yasmina Hanna | C5 - Agent Tools**

I drew the tool boundaries around intent and side effects. `search_catalog` answers an information request without writing to storage. `create_hold` carries out one explicit change for a known book and student. `reserve_book` owns the higher-level reservation workflow, coordinating the same search and hold implementations used by the other tools. The orchestration tool therefore has one user-facing purpose even though its implementation contains several steps. I deliberately avoided a general `library_manager` tool with an operation flag: its schema would mix unrelated inputs and make it harder for an agent to distinguish a lookup from a write. Typed results and specific errors make both successful and failed calls easier to interpret. Duplicate holds reuse their original identifier, and a SQLite transaction prevents simultaneous requests from taking the same last copy.

Three tools felt appropriate for this small use case because they capture information retrieval, a persistent action, and composition without duplicating interfaces. They are not enough for a production library service: there is no authenticated student identity, loan management, hold cancellation, or real university integration. A next version could connect a real catalog, enforce access controls, and define explicit cancellation and borrowing tools when needed. I would also evaluate live model routing across ambiguous requests and paraphrases, rather than infer broad reliability from a few examples. The verification checks domain behavior, MCP schemas, transport, and a scripted SDK run. A separate live OpenAI-backed run successfully routed all four recording scenarios, including the unavailable-book error; these results provide evidence for the demonstrated requests, while the final screencast remains to be recorded.
